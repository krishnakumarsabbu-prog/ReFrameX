01
Method & mechanics

How this report was produced

Reading order, scoring mechanics and the evidence discipline behind every number that follows.

Assessment pipeline
01

Ingest

Artifacts are stored byte-for-byte with SHA-256 digests, detected encoding, category and support level. No content is transformed at this stage.

02

Preprocess

Fixed-format records are rebuilt into logical lines, sequence/indicator columns are stripped, comments and blanks removed, continuation handled.

03

Parse

Language-specific parsers emit normalized components, each carrying an evidence reference of artifact, line range, rule and snippet.

04

Identify

Components are grouped into stable identities so the same paragraph or record keeps its identity across re-analysis runs.

05

Resolve dependencies

COPY members, CALL targets, transactions and datasets are linked. Unresolved targets are recorded as Unknown rather than guessed.

06

Evaluate rules

Every rule in the declared ruleset is evaluated against every applicable component or artifact. A rule either produces evidence or it does not; nothing is sampled.

07

Score

Domain results are normalized (hyperbolic saturation for complexity, baseline plus accumulated points for confidence and readiness) and weighted into the three top-level measures.

08

Publish

Scores, findings, evidence references and versions are persisted as an immutable assessment record. Reviewers append decisions; machine output is never overwritten.

Evidence classes
ClassIdentifierWhat it means in this report
Evidence-basedEvidence-basedRead directly from source at a specific file and line range.
InferredInferredDerived by analysis across evidence, with the derivation rule named.
AssumedAssumedTaken as working assumption; requires confirmation before it drives a decision.
UnknownUnknownReferenced but not resolvable from supplied material. Recorded, never silently dropped.

Every conclusion in this report carries one of these four labels. A finding is never presented as a fact when it is an inference, and an unresolvable reference is never discarded.

How the three measures are computed

Migration Complexity

complexity

How much work is this change likely to require?

100 × raw / (raw + K), K = 20.0

Each firing of a complexity rule adds its weight to the domain raw score. The hyperbolic curve saturates, so the first few findings matter most and additional findings have diminishing effect. That prevents a single noisy file from dominating the score. Only domains that produced evidence are included, and the domain weights are renormalised over those domains.

Assessment Confidence

confidence

How much of this application did we actually see?

min(Σ wᵢ·cᵢ + baseline, coverage × 100)

Confidence is a property of the evidence, not of the code. It accumulates positive rule points per domain, weighted by the ruleset domain weights, then is capped by the evidence coverage ratio so that an application with large blind spots cannot present high confidence.

Migration Readiness

readiness

Is there enough trustworthy information to plan the migration?

clamp(baseline + Σ positive − Σ negative, 0, 100)

Readiness reflects whether prerequisites for detailed planning exist: required artifact categories present, parsers succeeding, dependencies resolved, and no blocking unknowns. It is deliberately independent of complexity — a simple application can be unready if evidence is missing.

Classification thresholds
MeasureClassification bands
Migration ComplexityLow < 35 · Medium < 65 · High ≥ 65

Migration ReadinessNot Ready < 40 · Partially Ready < 70 · Ready ≥ 70
Determinism and reproducibility

The loaded ruleset contains 80 rules (34 complexity · 23 confidence · 23 readiness). Each rule is evaluated against every applicable component and artifact; no rule is sampled and no model inference is involved. The same inputs therefore produce byte-identical scores on every run, which is what makes two assessments of the same application comparable and auditable.

What this report is not. This is static extraction and deterministic scoring, not full semantic execution analysis. Absence of a detected risk is not evidence that the risk does not exist.

Domain weights and scope

Domain weights are declared in the ruleset, not inferred from the data. Complexity is renormalised over evidenced domains; confidence and readiness aggregate over all eight so that a blind spot pulls the score down instead of being ignored.
